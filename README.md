# MedQueue — цифровая регистратура


Профиль кандидата: **Media Technologies, 2 курс, Astana IT University**.

MedQueue помогает регистратору увидеть расписание дня, записать пациента на свободное время и провести его через этапы приёма. Это работающий локальный прототип: браузерный интерфейс, REST API и сохраняемая база SQLite.

Компания разрабатывает медицинскую платформу «Авиценна», поэтому тема связана с её предметной областью. Источник: [официальный сайт Cushpen Group](https://cushpengroup.com/), просмотрен 19.11.2026. Проект независимый: интеграция с «Авиценной», участие компании и соответствие её внутреннему отборочному заданию не заявляются.

## Запуск

Нужен Python 3.11 или новее. Node.js, ключи API и внешние сервисы не нужны. Интернет нужен только для первой установки Python-зависимостей. Проверено на macOS, Python 3.13.

В терминале перейдите в папку проекта:

```bash
cd medqueue
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8017
```

Откройте **http://127.0.0.1:8017**. Документация API: **http://127.0.0.1:8017/docs**.
Для остановки сервера нажмите Ctrl+C.

На macOS также можно запустить `Start.command` из Finder или командой `bash Start.command`. Скрипт создаёт локальное окружение в этой папке и при первом запуске устанавливает зависимости. Если порт занят, остановите предыдущий экземпляр или измените `--port` в команде выше.

На Windows используйте `py -3 -m venv .venv`, затем `.venv\Scripts\python -m pip install -r requirements.txt tzdata` и `.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8017`. Запуск на Windows не проверялся.

## Что работает

- Расписание по дню с фильтрами по врачу и статусу.
- Запись одного из 12 демо-пациентов к одному из 3 демо-врачей.
- Свободные интервалы по 30 минут, пн–пт, 09:00–17:00, перерыв 12:00–13:00.
- Запрет записи врача и пациента на два приёма в одно время, включая конкурирующие HTTP-запросы.
- Статусы: «Записан → В ожидании → На приёме → Завершён»; отмена до начала приёма.
- Ограничение одного текущего приёма у врача в выбранном дне.
- История создания и изменений через кнопку «⋯» у записи.
- Показатели дня и доля занятых интервалов каждого врача.
- Сохранение в SQLite после перезапуска, автоматические демо-данные при первом запуске.
- Компоновка для разных размеров экрана, текстовые обозначения статусов, клавиатурный фокус и модальные формы.

## Как показать за 3 минуты

1. Откройте демо-день: при первом запуске создаются 9 записей с разными статусами.
2. Нажмите «Новая запись»: пациент 10, невролог, свободное время 14:00 (если занято — другое).
3. У новой записи нажмите «Пришёл», затем «Начать» и «Завершить».
4. Нажмите «⋯» и покажите историю переходов.
5. Создайте ещё одну запись и отмените её: время снова доступно при новой записи.
6. Покажите сводку, фильтры и документацию API.

Если у выбранного врача уже идёт приём, сначала завершите его. После первого запуска демонстрационные данные сохраняются; набор статусов не сбрасывается автоматически. Для совершенно новой демонстрации можно запустить сервер с другим файлом базы:

```bash
MEDQUEUE_DB=data/fresh-demo.sqlite3 .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8017
```

### Ключевые решения

**Почему SQLite?** Один локальный файл, транзакции и SQL, без установки отдельного сервера. Для нескольких клиник и высокой нагрузки потребуются иная эксплуатационная архитектура и нагрузочные испытания.

**Как исключается двойная запись?** Уникальные частичные индексы на `(doctor_id, date, time)` и `(patient_id, date, time)` для всех неотменённых записей. Даже если два клиента увидели свободное время, база сохранит только одну запись; второй запрос получит HTTP 409.

**Почему интервалы фиксированные?** При единой длительности 30 минут уникальность начала исключает пересечение. Для произвольной длительности нужны проверки пересечения диапазонов — текущая реализация этого не поддерживает.

**Почему нельзя сразу завершить запись?** Разрешённые переходы заданы явно. Проверка текущего статуса, изменение и создание записи истории выполняются в одной транзакции `BEGIN IMMEDIATE`.

**Что означает загрузка?** Количество неотменённых записей / 14 доступных интервалов в рабочий день. Завершённые входят в число занятых интервалов. Это загрузка расписания, а не эффективность врача и не время ожидания. Показатели дня не меняются при фильтрации таблицы.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | Доступность приложения и базы |
| GET | `/api/config` | Даты и параметры демонстрации |
| GET | `/api/doctors` | Врачи |
| GET | `/api/patients` | Демо-пациенты |
| GET | `/api/slots?date=YYYY-MM-DD&doctor_id=1` | Свободные интервалы |
| GET | `/api/appointments?date=YYYY-MM-DD` | Записи; фильтры `doctor_id`, `status` |
| POST | `/api/appointments` | Создание записи |
| PATCH | `/api/appointments/{id}` | Изменение статуса |
| GET | `/api/appointments/{id}/history` | История |
| GET | `/api/summary?date=YYYY-MM-DD` | Показатели дня |

Тело создания: `{"doctor_id":1,"patient_id":10,"date":"YYYY-MM-DD","time":"14:00"}`.
Тело смены статуса: `{"status":"arrived"}`.
Ответы: 201 — создано, 404 — объект не найден, 409 — конфликт, 422 — неверный ввод.

## Проверки

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m unittest discover -s tests -v
```

Тесты создают отдельные временные базы, не изменяют локальные пользовательские записи и не требуют интернета. Проверены конфликты врача и пациента, параллельные запросы, отмена, переходы статусов, история, валидация, выходные, фильтры и перезапуск.

## Границы прототипа

- Только вымышленные пациенты и врачи, без ИИН, телефонов, диагнозов и медицинских документов.
- Нет аутентификации и ролей; запуск предназначен для `127.0.0.1`, не для публичного сервера.
- Все врачи работают по одинаковому расписанию. Нет праздников, отпусков, разной длительности и переноса записи одним действием.
- Запись возможна от сегодня до 90 дней вперёд. Для удобства демо допускается любое время сегодняшнего дня, включая прошедшие часы. Изменять статусы можно и в историческом дне.
- Клиенты не получают изменения в реальном времени: после собственного действия данные обновляются, изменения из другой вкладки видны по кнопке «Обновить».
- Журнал хранит переходы, но без идентификации сотрудника и защиты от редактирования администратором базы.
- Для справочников нет форм создания/редактирования. Демонстрационные люди заданы в коде.
- Эффект на работу клиники и удобство для реальных регистраторов не измерялись.
- Swagger UI загружает стандартные ресурсы документации извне; основной интерфейс работает локально после установки зависимостей.
